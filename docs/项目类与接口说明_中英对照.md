### 1.2 命名与阅读约定 / Conventions

- `Class / 类`：Python 类或 Django 模型类。
- `Method / 方法`：类内定义的函数或 `@property` 属性。
- `Interface / 接口`：HTTP URL 端点，以及服务层/权限层的公共函数。
- `Permission / 权限`：`RolePermission.permissions` 中的权限码，例如 `inbound.create`。
- `PK`：主键 / Primary Key。
- `—`：无额外权限要求，仅要求登录。
- “登录”指任何已认证用户；“申请人/主管”等业务限制在视图或服务层二次校验。

### 1.3 请求链路 / Request Flow

```text
Browser
  → tcm_wms/urls.py
  → warehouse/urls.py
  → View function
      → @login_required
      → has_perm() / business ownership check
      → Form / FormSet validation
      → Service function (transaction.atomic)
          → Model / ORM
          → StockMovement / OrderStatusLog
  → messages + redirect
  → Template render
```

## 3. 业务服务接口 / Domain Service Interfaces

### 3.1 `WorkflowError` / 业务异常

**Purpose / 用途：** 服务层可预期业务错误的统一异常，视图捕获后转为用户消息。  
**Base / 基类：** `Exception`。  
**Usage / 用法：** `raise WorkflowError("库存不足")`。

### 3.2 公共业务函数 / Public Service Functions

| Function / 函数 | Signature / 签名 | Description / 说明 | Transaction & effects / 事务与副作用 |
| --- | --- | --- | --- |
| `submit_order` | `submit_order(order, user)` | 提交移库/出库单，校验同仓、库位不同、库存预检，状态改为 pending。 | `atomic` + 行锁；写 SUBMIT 轨迹，不扣库存。 |
| `approve_order` | `approve_order(order, user, comment="")` | 审核通过/验收入库单；禁止申请人自审。 | 状态 approved；写审核人/时间/意见与 APPROVE 轨迹。 |
| `reject_order` | `reject_order(order, user, comment)` | 驳回待审核/待验收单据，意见至少 2 字。 | 状态 rejected；记录驳回意见与轨迹。 |
| `complete_transfer` | `complete_transfer(order, user, comment="")` | 确认移库：源库位扣减、目标库位增加。 | 锁源/目标库存；2 条流水；状态 completed。 |
| `complete_outbound` | `complete_outbound(order, user, comment="")` | 确认出库：扣减指定库位库存。 | 锁库存；1 条流水；状态 completed。 |
| `submit_inbound` | `submit_inbound(order, user)` | 提交入库单验收；校验至少一条明细、库位归属、批次号。 | 状态 pending；写 SUBMIT 轨迹。 |
| `complete_inbound` | `complete_inbound(order, user, comment="")` | 确认入库：逐条创建/合并库存批次。 | 每条明细写 INBOUND 流水；状态 completed。 |
| `cancel_order` | `cancel_order(order, user, reason="")` | 取消未完成单据。 | 状态 cancelled；写 CANCEL 轨迹；不改库存。 |

## 5. HTTP 接口 / HTTP Interfaces

### 5.1 约定 / Conventions

- 所有业务页面默认要求登录；POST 动作要求 CSRF Token。  
- All business pages require authentication; all POST actions require a CSRF token.
- “权限”列是接口级 `has_perm()` 检查；没有写权限的接口仍可能在视图内做“申请人/上传人”归属检查。
- The Permission column is the endpoint-level permission check; ownership checks may additionally apply.
- 返回 HTML 页面或 302 跳转；CSV 导出返回 `text/csv`；JSON API 返回 `application/json`。
- Most endpoints return HTML or 302; exports return CSV; the batch API returns JSON.

### 8.5 扩展新接口的步骤 / Adding a New Interface

1. 在 `access.py` 增加菜单/权限码（如 `report.audit`）。  
   Add the menu/permission code in `access.py`.
2. 在对应的 `*_views.py` 写视图函数，使用 `has_perm()` 或 `permission_required`。  
   Add the view and protect it with `has_perm()`.
3. 在 `warehouse/urls.py` 注册 URL name，并在 `MENU_URL_NAMES` 中补充菜单映射。  
   Register the URL name and menu mapping.
4. 在模板中通过 `role_permissions` / `allowed_menus` 控制菜单和按钮显示。  
   Gate menu/buttons with `role_permissions` / `allowed_menus`.
5. 若涉及库存，必须通过 `services.py` 的事务函数执行，不允许直接改 `StockBatch.quantity`。  
   All stock changes must go through `services.py`.
6. 增加测试：权限、状态、正常路径、异常路径、库存前后值。  
   Add tests for permissions, states, success, failure and stock values.

### 8.6 重要约定 / Important Conventions

- **单号 / Order numbers：** 移库 `YK`、出库 `CK`、入库 `RK` 前缀。  
- **库存 / Inventory：** 唯一维度为 `Herb + StorageLocation + StockBatch.batch_no`。  
- **并发 / Concurrency：** 所有库存动作使用 `transaction.atomic()` + `select_for_update()`。  
- **审计 / Audit：** 业务单据、库存流水、状态轨迹在 Admin 中只读。  
- **附件 / Attachments：** 只允许移库/出库单，单文件 ≤ 5 MB，必须且只能关联一张单据。  
- **权限 / Permission：** 默认角色配置可被数据库覆盖，超级管理员兜底全部权限。
